    * Pick 5, focus on 3 most challenging - shopping cart, order processing and viewing a customer's order history.
    * shopping cart
      * <img width="450" height="250" alt="image" src="https://github.com/user-attachments/assets/25b44a95-eef0-4b16-92a6-087fe57321a7" />

      * globally distributed
        * If a region has an outage, don't want an outage in our shopping cart.
        * people able to add and view cart no matter what is happening in a given cloud region.
        * picked a database that works in multiple cloud regions,
      * care about the data being consistent.
        * If a user makes a change to a cart in one region, he should see that exact same change reflected in other regions.
      * need all of these interactions to be low latency because any type of latency friction will cause a drop off or conversion problem.
      * Cosmos DB provides all of these.
        *  create a cart container that operates in multiple regions and uses session consistency.
        * This provides lower latency and better availability for rights than globally strong consistency.
      * <img width="450" height="250" alt="image" src="https://github.com/user-attachments/assets/c40fadc7-258e-40a9-b621-260fd524221c" />
        * After this set of steps (user add cart, response back to user) has finished the region, region goes down outage, but now the user wants to view his cart because we stored the session token in the cookie.
      * <img width="500" height="275" alt="image" src="https://github.com/user-attachments/assets/c361aa68-61a1-495f-aa73-5f08f670cee3" />
        * The user will present that session token to view cart -> presentation tier -> application tier -> call query ->
          * If the data has been replicated from the 1st region to the 2nd region by the time this call is made, the item will be found and returned to the user.
          * So the user can view a consistent cart.
        * But if there are any delays in replication, rather than showing the user an inconsistent cart,
          * what will happen is the application tier will continue to retry until it syncs with the initial region at which point it will show the final cart.
        * The design provides a globally consistent low latency shopping cart and it's exactly what we need for our application.
